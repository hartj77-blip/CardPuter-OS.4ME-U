Monochrome

A black, white and grey interface for the Cardputer Zero's 320 × 170 screen. Large-format landscape photography on home and lock, a strict 4 px grid everywhere else, and inverted white for focus instead of an accent colour. Menus get BlackBerry-style depth: soft vertical gradients and a lifted sheet. App icons stay exactly as their authors drew them, and status colours stay.

Screens

Every mockup below is built at the device's real 320 × 170 pixels and scaled up, with the keys, soft-key bars, menu letters and tiles that ZeroOS uses today (docs/UX.md, docs/KEYS.md). This is a new skin on UI 2, not new navigation. Photography is The Tetons and the Snake River (Ansel Adams, 1942), a public-domain National Park Service print.

Colour

Nine greys, each a value RGB565 can show exactly or near enough, so nothing tints green on the panel. Status colours stay: kGood #3fb950 (installed, connected), kWarn #f0a020 (update, low battery), kInfo #3b9eff, kDanger #e5484d (destructive). They mark state only, never decoration. "On" is white, "off" is outline.

Type

Inter (SIL OFL) replaces Ubuntu, built with the existing tools/fonts.sh. Five sizes, nothing in between: 9, 11, 14, 20, 46 (lock clock only, digits only). Tabular numerals on. Section labels 7 px caps, +14% tracking.

Grid

Unchanged from UI 2 so no screen re-flows: 4 px unit and margin, status bar 20, soft-key bar 14, rows 22 (6 per screen), two-line rows 32, menu rows 18, menu 168 wide. Radius 0 for system chrome; borders 1 px, never 2.

Gradients

Soft, vertical, greyscale. kRaise (#232323 → #0a0a0a) on menus, dialogs, the status and soft-key bars; kFocus (#fff → #cfcfcf) on the item in focus. Plus the photo scrim and slider fills. Never more than two stops of grey, never on body text.

Rules

  • Focus is inversion: a white row with black text. No accent colour exists to reach for.
  • Photography appears on home and lock only. Every other screen is solid k0, so text contrast never depends on the picture.
  • System chrome is square. Menus and dialogs get depth from a gradient and a shadow, not from rounded corners.
  • An app's icon belongs to its author. The shell draws it as given, whatever its colours or shape, and only adds the focus ring.
  • Colour is a message. Green, orange, blue and red mark state; content (app icons, album art, photos) keeps its own colour. The chrome never does.
  • Apps take chrome colours, sizes and spacing from theme.h tokens. A hex literal outside theme.h and an app's own icon fails CI.

Plan

Ordered so the device looks consistent after each step. Each phase is its own pull request against main, with emulator screenshots attached.

Phase 1
Tokens

Rewrite the theme, change nothing else

  • Replace the Yaru constants in shell/src/ui/theme.h with the k0–k8 ramp, kDanger and role names (kFocusBg, kFocusFg, kHairline, kTextSecondary).
  • Keep the old names as aliases pointing at greys for one release, so CardPuter-Apps builds keep compiling.
  • Radius 0 in style_panel and style_focus_list; focus becomes white/black in theme.cpp and in lv_theme_default_init (shell.cpp:153).
Phase 2
Photography

Built-in prints only

  • tools/wallpaper.py, run at build time: crop to 320 × 170, convert to 8-bit greyscale (LVGL L8, 54 KB instead of 108 KB as RGB565), bake the scrim in, ordered-dither so it doesn't band on the 16-bit panel. Output a C array compiled into the shell. No image decoder on the device.
  • Ship public-domain Adams prints from the 1941–42 Mural Project (National Archives series 79-AA): Tetons and the Snake River for home and lock, perhaps one or two more to choose between in Settings › Display. No custom wallpapers. Credits go in the About screen and the LICENSE third-party list.
  • Replace the aubergine gradient in launcher.cpp build() with the image + scrim.
Phase 3
Chrome

Status bar, soft-key bar, home, menu, toast, panel

  • Status bar transparent over photos, solid black with a hairline elsewhere; battery drawn as an outline glyph with a percentage.
  • Soft-key bar: keycap chips (1 px border) instead of filled grey; text k6.
  • Home pins and recent rows draw each app's own icon as its author made it, with a white focus ring instead of the orange tile highlight.
  • Tab menu, toast, confirm and quick panel restyled to the lifted sheet above: kRaise gradient, 1 px top highlight, drop shadow, a title row naming the item, and a kFocus bar on the selection. LVGL draws all of this natively (bg_grad, shadow_width); keep shadows on overlays only so lists stay fast.
  • New lock screen (power.cpp): photo, 46 px Inter Light clock, now-playing line.
Phase 4
Type & icons

Inter and outline glyphs

  • Regenerate zs_font_* from Inter at 9/11/14/20 plus a digits-only 46 for the clock; drop 12, 16, 28 after Phase 5.
  • System glyphs (status bar, menu items, file types) move to an outline set (Material Symbols, Apache 2.0) at weight 300. App icons are not touched: whatever image or glyph and colour an app's author ships is what home shows.
Phase 5
Apps

Sweep both repositories

  • Replace hex literals in the 78 files that have them (this repo's shell/src and CardPuter-Apps apps/) with tokens; app icon colours (AppInfo::color, the palette in m5_apps.cpp:115) are content and stay.
  • Add a CI check that fails on 0x[0-9a-f]{6} outside theme.h.
  • Remove the Phase 1 aliases and bump ZS_APP_ABI.
Phase 6
Docs & ship

Mockups, emulator, release

  • Redo docs/ux/mockups.html and its PNGs in this style. In docs/UX.md › Layout, replace the colour paragraph and "the focused row is the accent colour, 4 px radius" with the tokens here, and set the status bar to 20 (what the code uses). Keys, kinds of screen and the kit stay as written.
  • Refresh the browser emulator build and README screenshots; cut the next minor release (0.7.0; 0.6.0 is already out) and update the README's newest-release line.

Risks

RiskWhat we do
Grey banding in photosPick ramp values that map cleanly to 565; dither the photos at build time, not on device.
Bright app icons fight the grey chromeThat's intended: icons are the colour on the screen. Focus ring is white so it reads against any icon.
Gradients band on RGB565Keep gradients short (one bar or sheet tall) and between close greys; turn on LVGL dithering if they step.
Photo or shadows slow the CM0A 54 KB L8 blit is cheap and the scrim is baked in. Shadows only on the one open overlay; measure frame time in Phase 3.
Contrast on bright framesText only over the scrimmed band; check every shipped print at 4.5:1 for 11 px text.
Breaks third-party appsAliases for one release, then the ABI bump the Apps store already understands.
